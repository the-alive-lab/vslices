# Docs Standard — anti-bureaucracy

**Owner:** VSlices Docs Standard.

**Criterion:** preserve the smallest useful structure on which future work depends.

## Nine criteria

1. **No artifact mandatory by default.** Availability does not create documentary obligation.
2. **Smallest useful expression.** A Support Note can suffice; a Document need not answer every branch, a Nexus need not instantiate every recommended perspective, and a Path need not traverse all possible routes.
3. **Volume is not understanding.** Evaluate useful preserved meaning rather than pages, nodes or files.
4. **Do not claim knowledge not established.** Distinguish evidence, assumptions, uncertainty and invalidated beliefs.
5. **Avoid false completeness.** Unanswered branches can be intentionally irrelevant or deferred, rather than missing work.
6. **Keep knowledge related to decisions.** Preserve connections with context, realization and subsequent evidence when relevant.
7. **Treat obsolescence as risk.** Keep historical claims discoverable without silently presenting them as valid.
8. **Split or compose only for clarity.** Avoid fragmentation or duplication justified only by a taxonomy.
9. **Justify documentary cost.** Simplify when maintenance exceeds the continuity protected.

Epistemic labels like known/assumed/unclear or unknown/deferred can help but are **not** new mandatory YAML enums. Old minimal/expanded/reference language expresses proportionality, **not** the former L0–L3 progression.

## Provenance

Preserves all nine concerns from the [historical public anti-bureaucracy rules](https://github.com/vslices/docs/blob/main/es/products/docs-standard/how-to-use/anti-bureaucracy-rules.md), adapted to the current four artifact responsibilities without reinstating old document levels or taxonomies.
