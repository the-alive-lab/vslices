# Docs Standard — compliance-support boundary

**Owner:** VSlices Docs Standard. **Status:** conceptual boundary, not a certification or legal opinion.

Docs Standard primarily preserves engineering knowledge and continuity. It **does not, by itself, establish conformity** with laws, external standards, audits or organizational controls.

The preserved intent, context, decisions, behavior, validation and evolution can support compliance analysis, but actual conformity requires identifying the external requirement, mapping existing evidence, finding gaps and adding any mandatory reviews, controls, approvals, tests or regulatory evidence.

## Three distinctions

- **Supports:** the preserved knowledge assists a requirement-relevant question.
- **Partially supports:** useful knowledge exists but required form, verification or control is absent.
- **Requires addition:** external obligations demand artifacts, evidence, authorization or procedures Docs Standard does not supply.

Continuity Paths may help traverse evidence but do not replace audit mechanisms or constitute mandatory full traceability.

## Historical examples, not verified conformity

The public source discusses ISO/IEC/IEEE 42010, ISO/IEC/IEEE 29148, arc42, C4, ADR and 4+1 as possible mapping targets. These examples are **not** claims that current VSlices satisfies those external standards. Their original comparison table remains historical guidance, not a normative compliance matrix.

**Rule:** preserve engineering continuity first and add formal compliance obligations only where the actual context requires them.
