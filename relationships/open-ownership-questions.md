# Open ownership questions

## Purpose

These questions are deliberately unresolved.

They prevent the suite surface from silently taking authority away from an existing product merely because a broader organization now appears attractive.

## Continuity Path

### Current evidence

Existing Docs Standard sources treat `Continuity Path` as a Docs Standard meta-structure.

### New pressure

The proposed Orientation Path is used to establish enough continuity for the VSlices lifecycle itself, and Method may depend on it when entering and closing iterations.

This creates a real ownership question:

```text
Continuity Path
    = Docs Standard mechanism?

or

Continuity Path
    = VSlices continuity mechanism
      realized documentarily by Docs Standard?
```

### Current decision

Do not change ownership yet.

The new pressure is evidence for investigation, not authority to reinterpret the existing model retroactively.

## Lifecycle ownership

The current working lifecycle coordinates several products:

```text
Orientation
-> Understanding
-> Contextualizing
-> Planning
-> Building
-> Feedback
-> Orientation
```

Method has the strongest current ownership affinity because it organizes how work navigates products and modalities.

Question:

```text
lifecycle
    = Method-owned navigation model?

or

lifecycle
    = suite-level mechanism used by Method?
```

Current decision: keep the lifecycle candidate, record Method affinity, and avoid premature promotion.

## Work forces ownership

Semantic, Technical, Delivery, and Resource forces affect the direction of effort across organizational and system perspectives.

Design has the strongest current ownership affinity because the forces influence modality and candidate realization.

Current decision: preserve them as a Design-affine candidate model until repeated use clarifies whether any part belongs to the suite itself.
