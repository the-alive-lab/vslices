## Interpretation chain and boundaries

```text
Organization/project evidence (source authority)
  -> Docs Standard documentary identity, provenance, relationships
  -> Method's candidate classification/reinterpretation of Orientation Factors
       (interpreted change/nuance + reasons = impact)
  -> explicit Docs Standard front-matter relations identify possible receivers
  -> Tooling-supported traversal (NOT implemented at present)
  -> next document interpretation (candidate Method responsibility)
  -> Method's candidate Value Orientations response space
  -> Method Modality Selection
  -> Design modality semantics
  -> Protocols / authorized group execution
```

This is a **responsibility representation**. It is **not** a claim that Tooling already supports relationship traversal, that Docs Standard owns Method's semantic judgments, or that a model is authorized to change client facts. Human and LLM interpretations must remain traceable and corrigible.

## Explicit unresolved boundaries

1. **Orientation Factors vs historic Design-owned-affine Work Forces.** Are these the same concept with revised ownership, or distinct semantic aspects: Method's evidence-to-priority interpretation and Design's organizational/system work geometry? Preserve Design affinity until contrasted.
2. **Documentary Reinterpretation scope.** Its current factor interpretation is Method-affine. If generalized to other documentary meanings, ownership might shift to a Suite mechanism or require a distinct shared kernel. Do not generalize from one use case.
3. **Value Orientations scope.** Selection-oriented usage supports Method affinity but does not establish exclusive Method ownership; possible Suite-level applicability requires independent evidence.
4. **Relationship traversal semantics.** Use Docs Standard's **already-defined** front-matter relation contract when support is implemented; do not invent a new property, treat tags as traversal, or assume all relations are symmetric/traversable.
5. **Data and authority.** Evidence from clients, project sources and third parties may disagree; a document or LLM interpretation does not become business authority merely by being included in the graph.

**Decision for PR #2:** publish the allocation as an explicit *candidate ownership map* and keep previous affinity notes as history. No repo rename, conceptual promotion or Tooling implementation is enacted by this document.
