# Promotion

## Purpose

VSlices must be able to reconstruct how an idea moved from observation to definition without pretending it was always stable.

Candidate trajectory:

```text
observation
-> candidate idea
-> repeated evidence
-> conceptual stabilization
-> ownership decision
-> promotion
-> canonical definition
```

## Minimum questions

Before promoting an important concept:

1. What does it mean?
2. What kind of knowledge is it?
3. Who has primary authority to define it?
4. Who uses it?
5. Where is it defined today?
6. What evidence supports or challenges it?
7. What is its maturity?
8. What relationships does it maintain with other concepts?

## Candidate knowledge kinds

- Foundations;
- Mechanisms;
- Product-owned concepts;
- Principles;
- Hypotheses;
- Evidence.

These labels should not become a rigid physical taxonomy merely because they are useful.

## Non-duplication rule

```text
definition
!= history
!= evidence
!= public projection
```

A canonical definition may link to history and evidence without absorbing them.

## Publication

Only after authority and definition are organized should VSlices decide how the knowledge is projected publicly.

```text
canonical knowledge
-> deliberate public projection
-> documentation site
```

Public navigation may optimize onboarding and learning without becoming the accidental internal ontology of VSlices.
